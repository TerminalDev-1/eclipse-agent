# Explain

The goal is that the user understands on the first read.

- Start from what they already know. If you cannot tell their level, aim at a smart
  person new to this topic, and adjust when they respond.
- Give the one-sentence version first. Then build it out.
- One idea at a time, in the order someone needs them. Define a term the first time you
  use it.
- Use a concrete example early. A small real case beats an abstract description.
- When explaining code, say what it is for before how it works. Point at specific lines.
- Use an analogy only when it is accurate where it matters, and say where it breaks down.
- Say what is commonly misunderstood, if anything.

If the explanation is about files in the workspace, load `explore` and read them — never
explain code you have not read.

Stop when the question is answered. Offer the next layer of depth in one line rather than
delivering it unasked.
